Item 4: Technical Documentation & Standard Operating Procedures (SOPs)

4.1 Platform Stack Specifications

  • Core Framework: Next.js 16 (React 19, App Router architecture)
  • Database & ORM: PostgreSQL 16 on Neon, managed with Prisma ORM v6
  • File Storage: Cloudflare R2 (S3-compatible, zero egress fees)
  • Authentication: NextAuth.js v5 (stateless JWT session strategy)
  • Payment Engine: Razorpay Orders, Subscriptions, and HMAC webhook verification
  • Email Delivery: SendGrid with secondary Resend and SMTP failover
  • AI Intelligence: OpenAI API (structured resume extraction & ATS ranking)

4.2 Operational Runbooks (SOPs)

SOP-01: Local Environment Setup

  1. Clone repository: git clone https://github.com/matheletes111-afk/jobs-wala.git
  2. Install dependencies: npm install
  3. Generate Prisma client: npm run db:generate
  4. Start development server: npm run dev (Server runs on http://localhost:3000)

SOP-02: Production Deployment on Vercel

  1. Any commit pushed or merged into the main branch automatically triggers a production build on Vercel.
  2. To trigger a manual redeployment without pushing code: Navigate to Vercel Dashboard > jobdaddy > Deployments, select the latest deployment, and click Redeploy.
  3. Build command: next build --webpack | Postinstall command: prisma generate.

SOP-03: Running Database Migrations with Prisma

  • To create and apply a migration during feature development: npm run db:migrate
  • To push schema changes directly to staging/production: npm run db:push
  • To inspect and edit live database tables graphically: npm run db:studio (launches Prisma Studio at http://localhost:5555)

SOP-04: Creating Administrative Accounts

  1. Set admin credentials in environment: 
    ADMIN_EMAIL="admin@jobdaddy.in" ADMIN_PASSWORD="SecurePassword123!" npm run create-admin
  2. Log in via https://www.jobdaddy.in/login. The account has instant access to https://www.jobdaddy.in/admin.

SOP-05: Cloudflare R2 Storage Management

  • Resumes and logos are uploaded using presigned URLs generated in lib/s3.ts.
  • If uploads fail with a CORS error, check that the R2 bucket settings allow origins https://www.jobdaddy.in and https://jobdaddy.in for methods GET, PUT, POST, HEAD.
  • Bucket name: jobdaddy. Public preview URL: https://pub-77077181400d4766a0a4b6fdbf5d14cb.r2.dev.

SOP-06: Razorpay Payments & Webhook Handling

  • Payment flows are implemented in lib/razorpay.ts and app/api/webhooks/razorpay/route.ts.
  • Webhook URL: https://www.jobdaddy.in/api/webhooks/razorpay.
  • Events enabled: payment.captured, order.paid, subscription.charged.
  • To switch to Live Mode: Replace RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET with live keys in Vercel Environment Variables.

SOP-07: Incident Response & 1-Click Rollback

  • To check runtime errors: Go to Vercel Dashboard > Logs > filter by Status 500+.
  • Immediate Rollback: If a deployment has an issue, go to Vercel > Deployments > select the prior stable deployment > click Promote to Production. Traffic is reverted in under 5 seconds.
